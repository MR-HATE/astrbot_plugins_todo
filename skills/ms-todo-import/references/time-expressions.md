# 时间表达速查

工具内部会兜底解析下面这些写法，但**优先由你换算成绝对日期**——你的换算更准，
而且用户能从预览里立刻发现错误。

## 日期

| 写法 | 解析结果 |
| --- | --- |
| `今天` `今日` `当天` | 今天 |
| `明天` `明日` | +1 天 |
| `后天` / `大后天` | +2 / +3 天 |
| `3天后` | +3 天 |
| `周三` `星期三` `礼拜三` | 最近的周三（含今天） |
| `下周三` `下个星期三` | 下一个自然周的周三 |
| `2026-09-18` | 当天 |
| `9月18日` `9月18号` | 今年的 9/18；若已过去则顺延到明年 |
| `12/01` `12-01` | 今年的 12/1 |

**不支持**（会忽略该项的日期并在预览里提示，此时你要向用户说明）：
`月底`、`下个月`、`月初`、`季度末`、`国庆前` 这类没有唯一确定日期的说法。
遇到它们就留空，或先问用户"具体哪一天"。

## 时刻

| 写法 | 解析结果 |
| --- | --- |
| `9:00` `09:00` | 09:00 |
| `9点` `9点整` | 09:00 |
| `9点半` | 09:30 |
| `9点30` `9点30分` | 09:30 |
| `9点一刻` / `9点三刻` | 09:15 / 09:45 |
| `下午3点` `晚上8点` `早上7点半` | 15:00 / 20:00 / 07:30 |
| `九点` `下午三点` `晚上十点` | 09:00 / 15:00 / 22:00 |
| `十二点` | 12:00（有「上午」则 00:00，有「中午」「下午」则 12:00） |

**日期和时刻可以写在一起**：`9月18日 20:00`、`明天 下午三点`、`下周三晚上八点` 都能拆开解析。

## 时区

- 你只需要输出**本地时间**（`YYYY-MM-DDTHH:MM`），不要带 `Z` 或 `+08:00`。
- 如果确实带了偏移量（例如照抄了 `2026-09-15T12:00:00Z`），插件会**按配置时区换算**，
  并在预览里注明"已按配置时区换算"。不要让用户去猜 UTC 和本地的差值。

## 提醒（remind_at）

- 格式：`YYYY-MM-DDTHH:MM`（本地时间）。
- **只在用户明确要求提醒时填**。用户说"记一下"不等于要提醒。
- 只给时刻（如 `下午三点`）时，插件会把它落在该待办的**截止日期当天**；
  没有截止日期才按今天算（已过则顺延明天）。
- 提醒时间已过去会被忽略并在预览里提示——这时要如实告诉用户，让他重新给个时间。

## 常见坑

| 情况 | 正确做法 |
| --- | --- |
| 用户说「下周五」而他此刻正是周五 | 指下一个自然周的周五，不是今天 |
| 用户说「这周末」 | 拆成周六/周日两个具体日期，或问清楚 |
| 用户说「春节前」 | 不要猜，留空并说明 |
| 用户说「每天」 | 不支持重复任务，按最近一次填并告知 |
| 用户说「出发前一天」 | 需要结合已知的出发日期换算；没有出发日期就先问 |
